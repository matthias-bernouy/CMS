# @bernouy/hub-ui

Superadmin UI for `@bernouy/hub-api`. SSR-light HTML pages + webcomponents
served on the **same runner** as the hub API, under `/admin/*`. Single
public entry : `mountHubUi(opts)`.

The cookie set by Keycloak superadmin login is shared natively between
`/admin/*` and `/api/*` (same origin) — no CORS, no token plumbing.

## Build step

`bun run build` (build.ts) bundles `src/components/index.ts` into
`src/assets/hub-components.js` as an IIFE — same approach as the CMS's
`prebuildControl`. The workspace root `build.ts` runs it, so the docker
image picks it up. Each component self-registers with the idempotent
`if (!customElements.get(...))` guard. Component CSS uses ONLY theme
tokens (`var(--…)`) — never a hardcoded color.

**CSS lives with its component.** `hub-ui.css` is GLOBALS ONLY — `html/body`
reset, font, the `w13c-left-menu-layout` host, and the `p9r-tab-panel`
visibility tweak (styling a slotted host that can't be reached from a shadow
root). Every visual class moved into a component's shadow `style.css`. Pages
are pure markup composed of `<hub-*>` + `<p9r-*>` elements — no class-based
styling, no `<style>` in pages. Surfaces reuse `p9r-card` (no `hub-card`).

## What `mountHubUi` does

1. Registers a **same-origin guard** (`requireRole(auth, "superadmin", { csrf: "cookie-only" })`).
2. Inside `/admin/*`:
   - `/assets/ui.js` → vendor'd from `@bernouy/webcomponents/dist/ui.js` (IIFE bundle, registers all `<p9r-*>` and `<w13c-*>`).
   - `/assets/style.css` → vendor'd from `@bernouy/webcomponents/dist/style.css` (theme tokens).
   - All HTML files under `src/static/` auto-routed via `serveStaticFolder` with the chrome template (`{{CONTENT}}` + `{{BASE_PATH}}` replaced).
   - Any non-HTML files in `src/static/assets/` served as-is (CSS, JS).

## Pages (sommaire)

| Path | Source | Hits |
| :-- | :-- | :-- |
| `/admin/` | `index.html` | `GET /api/namespaces`, `/api/providers`, `/api/issuer` |
| `/admin/namespaces/` | `namespaces/index.html` | `GET /api/namespaces`, `POST` |
| `/admin/namespaces/namespace?namespaceId=X` | `namespaces/namespace.html` | `GET /api/namespaces`, `GET /api/namespaces/tenants?namespaceId=X`, `GET /api/providers`, `POST /api/namespaces/tenants`, `PATCH`/`DELETE /api/namespaces` |
| `/admin/namespaces/tenant?tenantId=T&namespaceId=X` | `namespaces/tenant.html` | `GET`/`PATCH`/`DELETE /api/namespaces/tenants?tenantId=T`, `GET /api/namespaces/tenants/config`, `GET /api/providers` |
| `/admin/providers/` | `providers/index.html` | `GET`/`POST` `/api/providers`, refresh, delete |
| `/admin/providers/provider?providerId=X` | `providers/provider.html` | `GET /api/providers`, `GET /api/namespaces/tenants?providerId=X`, refresh, delete |
| `/admin/issuer` | `issuer/index.html` | `GET /api/issuer` |

Query forwarding: `<w13c-fetch url="/api/...">` re-appends the page's query
params, so `tenant.html?tenantId=T` makes `/api/namespaces/tenants` resolve
to that single tenant, `namespace.html?namespaceId=X` lists that namespace's
tenants, and `provider.html?providerId=X` lists that TP's tenants.

## Custom elements

| Tag | API |
| :-- | :-- |
| `<hub-json src path \| value>` | pretty-prints JSON; with `src` it fetches (page query forwarded) + resolves dot-`path`. Fixes the `[object Object]` interpolation bug. |
| `<hub-config-form schema value mode prefix>` | JSON-Schema → `<p9r-*>` form. `.getValues()`, `.isValid()`, `.rebuild()`. No nested objects / `x-visible-if` (v1). |
| `<hub-route-param param target>` | URL param → DOM substitution + `__PARAM__` placeholder rewrite. |
| `<hub-tenant-issuers tenant-id>` | `string[]` issuer editor → PATCH `/api/namespaces/tenants`. Empty list allowed. |
| `<hub-tenant-config-form tenant-id>` | loads TP schema + tenant config, renders `<hub-config-form>`, PATCHes `providerConfig`. |
| `<hub-add-tenant namespace-id provider-id label>` | one button → POST a tenant with `issuers:[]`; dispatches `tenant:created`. |

## Conventions

- **Build step**: `bun run build` bundles `components/` → `assets/hub-components.js`.
  Pages stay HTML-only; behaviour lives in custom elements / `<w13c-*>`.
- **No JS framework**. Dynamics via `<w13c-fetch>` + `<w13c-form>` + the
  custom elements above.
- **Theme tokens only.** Component CSS uses `var(--…)`; never a hardcoded color.
- **Same-origin.** All `/api/*` fetched same-origin; superadmin cookie attached natively.
- **Tests minimal**: one `mountHubUi` integration test (gated access + HTML). Pages untested.

## Wire avec hub-api

```
opérateur navigateur
    ↓ HTTPS + cookie superadmin
même Runner (Bun.serve)
    ├─ /admin/*    (mountHubUi)   → pages HTML + webcomponents
    └─ /api/*      (mountHubApi)  → endpoints hub-api
```

Côté composition root du déploiement :
```ts
const runner = new BunRunner();
const auth   = new KeycloakConsumer(...);   // superadmin Keycloak

mountHubApi({ runner, hub, auth });
mountHubUi ({ runner,      auth });

await runner.start();
```
