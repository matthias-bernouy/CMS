# Event initiator implementation

The CMS runtime seals `ulvia-event-initiator/v1` claims with the existing instance FieldCrypto adapter (tenant DEK, authenticated AES-GCM). The wire reference is `ei1.<iv>.<ciphertext>` with canonical base64url, bounded to 2048 UTF-16 units. It contains the instance/site, selected source owner, stable declaration ID, event type, producer occurrence ID and private actor. Providers cannot supply a CMS subject. Capture resolves the verified receiving Provider alias back to CMS identity; resolution generates the selected target Provider alias. No invocation token is persisted or extended.

Proof verification adds no database lookup: one authenticated decryption and keyed actor digest precede publication-receipt lookup. Capture adds the current source/declaration checks and, for a user, one identity-alias resolution. Native Forms currently performs a source resolution for capture and again for intent preparation. This favors explicit revalidation over a new cache. Resolution performs a current target-route check, a fresh administrator check for administrator calls, and one target-alias get-or-create. Causal inheritance uses one owner-scoped outbox metadata projection, `maxTimeMS: 2000`, without payload hydration. The existing ancestry lookup now shares that projection.

Provenance does not change GatewayActor, execution grants, subscription ownership, delivery deadlines or payload filtering. There is no provenance event-history endpoint. A retained proof is durable encrypted identifying metadata, with no login-style expiry. Its purpose/format and full source scope are verified after decryption; unrelated encrypted values cannot serve as proofs. CMS_SESSION_SECRET keys the actor fingerprint independently from randomized ciphertext, preserving retry deduplication. Tenant encryption-key availability and the existing configured session-secret stability are prerequisites for reopening retained state.

Forms event intents require an explicit nullable `initiatorProof`. Missing persisted fields refuse decoding rather than inferring or backfilling an actor. Existing installation state from an earlier unpublished experimental format is not rewritten. Rebuild/re-admit exact artifacts for fresh instances or perform an explicitly designed upgrade; the local lab's existing state must not be silently replaced.

Public capabilities execute with anonymous Gateway authority even if the HTTP caller presents a browser cookie. The provenance follows that verified context. Require an authenticated form and call `forms.submit-authenticated-v2` for a verified submitter; do not relabel a public submission from a payload field or cookie. The local laboratory makes this distinction explicit.
